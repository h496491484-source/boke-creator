# 故障处理

先看命令自己的输出：每个脚本停下时都会说原因和办法，给的命令能直接照抄运行。下面按"看到什么"查。

下文命令里的 `<技能>` 是技能目录，`<节目>` 是这期节目的目录，都换成完整路径、加引号，从哪个目录都能跑，比如 `node "<技能>/tools/podcast/status.mjs" "<节目>"`。带尖括号的占位（`<录音文件>`、`<文件夹>`）也一样，先换成真的路径。

## 安装

| 看到 | 原因 | 办法 |
|---|---|---|
| `node` 不是内部或外部命令 / command not found | 没装 Node | 用 WorkBuddy 的话，改用它自带的 `%USERPROFILE%\.workbuddy\binaries\node\versions\<版本>\node.exe`。其他情况到 https://nodejs.org 装 LTS 版，国内用 https://npmmirror.com/mirrors/node/ ，装完**重开终端** |
| 装了半小时还没好 | 多半是在等国外地址 | `node "<技能>/tools/setup.mjs"` 默认全走国内源（npmmirror、魔搭），几样同时装，正常一两分钟。大文件每 8 秒打印一次"已下 / 共"，看停在哪一项、有没有加 `--official`。技能本身用 git clone 或从 GitHub 一个个下载文件也会很慢，改用 zip 包 |
| setup 中途断了（断网、关了窗口、按了 Ctrl+C） | — | 再运行一次 `node "<技能>/tools/setup.mjs"`，会接着下（输出里有"接着上次的 xx MB 下"），不从头来。下到一半的文件是 `models/…/*.part`，自检会提示"没下完的" |
| setup"识别程序"没装成 | npmmirror 和 npm 官方源都没连上 | 换个网络再跑；或者用离线完整包 |
| setup"识别模型"或"播客精编用的模型"没下载下来 | 魔搭、hf-mirror、GitHub 都没连上，或者卡住（30 秒没数据）、太慢（每秒不到 50 KB）。这些都会自动换下一个来源；出过这种问题的来源这次就不再试。报错里写着每个来源的原因 | 先确认能打开 https://modelscope.cn ，再跑一次 setup（已下的部分接着用）；有别的国内地址可以设环境变量 `BOKE_MODEL_MIRROR=<地址>`；或者让已装好的人把 `models/sense-voice` 文件夹拷给你，然后 `node "<技能>/tools/get-model.mjs" --dir "<文件夹>"`（压缩包用 `--file "<压缩包>"`）；播客的三个小模型拷 `models/podcast`，用 `node "<技能>/tools/get-model.mjs" --podcast --dir "<文件夹>"`；或者直接用离线完整包 |
| 自检"配乐曲库"是提示：还差几首没下载 | setup 默认不下曲子，剪辑用到哪首当场下哪首 | 不用管；下不下来那一处先用 Aurora。想提前全下：`node "<技能>/tools/setup.mjs" --music`（或 `node "<技能>/tools/podcast/music.mjs" --download`） |
| setup 开头列出"清理旧版本留下的东西"；start / 自检提示"旧版残留" | 以前装过 v0.3 及以前的版本，新版解压覆盖上去后留下的旧依赖（几十到几百 MB）和旧版随包带的文件 | 正常，setup 运行时会删掉（删之前列出清单，setup 自己不再问）。先告诉用户会删哪些、他同意后再运行 setup（和 SKILL.md 开工那步一样）。删的是：`.state` 里 ffmpeg 以外的和旧的 ffprobe、`node_modules` 里识别程序以外的依赖和它们在 `.bin` 里的命令入口、`video-deps`，旧版随包带的模板、示例、说明和脚本（清单见 `tools/lib/leftovers.mjs` 的 OLD_FILES），还有技能目录第一层旧版的 `开发说明.md`、`.gitignore`（按内容认出是 v0.3 的才删，git 仓库里不删）。setup 换来源重装识别程序时临时挪开的 `.state/sherpa-onnx-<平台>.bad` 不算旧版残留，setup 装好或下次运行时自己删。**自己改过旧版模板的**，先运行 `node "<技能>/tools/setup.mjs" --check` 看清单（只看不删），把它另存成别的名字再跑 setup。别的文件不碰；删不掉的（被占用）不影响使用 |
| setup 说"setup 已经在跑了（进程 N）"，退出码 3 | 同一个技能目录已经有一个 setup 在跑（多半是放在后台的那个） | 等那个跑完、看它的输出，不要再开一个（两个一起下同一个文件会互相干扰）。进程已经没了的，锁会自动失效，直接重跑 |
| build 提示"配乐 xxx 没下载下来，先用默认的 Aurora" | 这期选的曲子本地没有，当场也没下下来 | 成品能用，只是那一处配的是 Aurora。补下载后重新运行 `node "<技能>/tools/podcast/finish.mjs" "<节目>"`（= build → check → notes） |
| 自检"配乐曲库"未通过：曲库文件读不出来 | 手改 `template/配乐/曲库.json` 改坏了 | 改回能读的 JSON，或者重新解压技能包 |
| ffmpeg 未通过 | 没装，或自动下载没成功 | 先 `node "<技能>/tools/get-ffmpeg.mjs"`（从国内镜像下，不行自动换 GitHub，Windows 和 Mac 都行；只要 ffmpeg 一个文件，不再要 ffprobe）；还不行：Windows `winget install Gyan.FFmpeg`，Mac `brew install ffmpeg`，装完重开终端再跑 `node "<技能>/tools/doctor.mjs"`。Windows ARM（骁龙）电脑：Windows 11 会自动下 x64 版（能跑）；Windows 10 ARM 跑不了 x64 版，要自己找 ARM 版 ffmpeg，把所在文件夹写进环境变量 `FFMPEG_DIR` |
| 识别程序"文件在，但加载不起来" | 识别程序的平台包缺文件，或者 dll 被杀毒软件隔离了 | 运行 `node "<技能>/tools/setup.mjs"`：第一次会删掉平台包，从国内镜像、npm 官方源轮流重装，每装一次都试加载（要联网）。都装上了还是加载不起来就不是包坏了，setup 会说原因（见下一行），以后也不会再删了重装；自检这时也直接给原因，不再叫重跑 setup。杀毒软件隔离的，先在杀毒软件里恢复、把技能目录加进信任 |
| setup 说识别程序"装好了，但加载不起来" | 不是网络问题。Windows 上多半是缺微软的 VC++ 运行库；也可能是杀毒软件隔离了 dll | 按 setup 给的链接装 VC++ 运行库（x64 电脑是 `vc_redist.x64.exe`），装完再运行 setup。重装过一次还不行，setup 下次不会再删了重装；确实想重装，删掉 `node_modules/sherpa-onnx-<平台>` 再运行 |
| setup 说"SHERPA_ONNX_DIR 指的……加载不起来" | 设了环境变量 `SHERPA_ONNX_DIR`，指向的那份识别程序坏了；它排在技能目录前面，setup 在技能目录里重装也没用 | 删掉这个环境变量（改用技能目录里装的），或者改成一份能用的，重开终端再运行 setup |
| Mac 上识别程序"加载不起来" | 系统拦了下载来的动态库；或者动态库位置没告诉系统（自检和转写都会自己设 `DYLD_LIBRARY_PATH`，一般不用管） | 系统设置 → 隐私与安全性里放行；或在终端运行 `xattr -dr com.apple.quarantine "<技能>/node_modules"`。还不行：把 `node -e "require('<技能>/node_modules/sherpa-onnx-node')"` 的报错发给帮你的人（没在 Mac 上实测过） |
| Mac：处理进程被系统结束了（SIGKILL / SIGTERM） | 内存不够被系统结束，或者被宿主的超时结束 | 关掉别的大程序，再运行同一条命令。Mac 上转写、分说话人、检查会另开一个子进程干活：要中途停掉，按 `<节目>/制作文件/` 里 `.lock` 文件记的进程号结束（只结束外层的命令，子进程可能还在跑）。`show.mjs`（看档案、`--learn` 记声纹）在 Mac 上也会另开子进程，但不记锁：几秒到几十秒就完，一般不用停；真要停，在活动监视器里结束命令行带 `show.mjs` 的两个 node 进程 |
| 任何一条命令退出码 1，输出最后只有一行 `Node.js v…`（上面是英文的 `Cannot find module`、`EPERM`、`SyntaxError` 之类，可能被截掉了没看到） | 技能自己的脚本当时读不到：正在覆盖安装、更新或者 git 切换技能目录，同步盘、杀毒软件正占着刚放进来的文件。技能自己报的错都是中文，不会只剩这一行（v0.7 发布前第 3 轮测到过一次，没能复现） | 等安装、同步、扫描完了，原样再运行同一条命令（这类错发生在开工之前，什么都没动）；还这样运行 `node "<技能>/tools/doctor.mjs"`，把那条命令的完整输出（连英文那几行）发给帮你的人 |

安装可以反复跑，装好的会跳过。全部东西都在技能目录里；想彻底重装，删掉里面的 `node_modules`、`.state`、`models`、`boke-creator.local.json` 再跑 setup。

## 播客精编

| 看到 | 原因 | 办法 |
|---|---|---|
| start.mjs【环境】有几项没过 | 还没安装，或装了一半 | 告诉用户要下载约 300 MB（配乐曲库默认不下），同意后运行 `node "<技能>/tools/setup.mjs"`；完整自检用 `node "<技能>/tools/doctor.mjs"`（会真的加载一次识别程序） |
| 节目目录第一层没有录音文件 | 还没放录音 | 用 `node "<技能>/tools/podcast/new.mjs" "<节目>" "<录音文件>"` 放进来（同一个盘是硬链接、别的盘只记位置，都不另占空间，也不挪原文件；要一份和原文件互不影响的拷贝加 `--copy`）。不要自己用 Copy-Item / Move-Item 复制或挪动录音：复制白占几百 MB，挪走了用户就找不到原文件 |
| 节目目录第一层没有录音文件（录音在节目目录的子文件夹里） | 录音放进了节目目录下面的子文件夹 | 挪到节目目录第一层就行 |
| new.mjs：这是视频文件 / 不是能用的录音格式；transcribe / status：节目目录里有「……」，但是视频或格式不认 | 给的是视频（mp4、mov……），或者录音格式不在支持的列表里（能用的：mp3、m4a、wav、flac、aac、ogg、opus、wma、amr、aiff、caf） | 视频照输出里给的 ffmpeg 命令先把声音提取出来（`-vn`），别的格式先转成 wav 或 mp3，再用 new.mjs 放进来 |
| transcribe / status：录音找不到了（开这期时登记的位置是……） | 录音在别的盘上（或者在不支持硬链接的 U 盘上），开这期时没拷进节目目录，只在 `录音位置.json` 记了位置；后来原文件被移走、删掉、改了名，或者那个盘（U 盘、移动硬盘）没插 | 放回原处或插上那个盘；挪到了别处就 `node "<技能>/tools/podcast/new.mjs" "<节目>" "<录音的新位置>"` 重新登记，做完的不会重做。文件名也改了照样这么做：大小一样的（旧版登记没记大小的：只丢了这一个、这次也只给一个）会自动换掉找不到的那条、名字照旧。换不掉时 `new.mjs "<节目>" --forget <找不到的录音名>` 去掉旧登记再登记新的（名字变了，要整期重新转写）。找不回来：已经出的全文、方案、精编版都还在，只是不能再重新转写、重剪 |
| status：注意，转写时用的录音「……」不在节目目录里了 | 节目目录里的原始录音被删掉、挪走或者改了名（几段录音少了一段也算） | 放回节目目录、名字和原来一样。找不回来就别清理中间文件（clean 会拦下）：清了就再也没法重剪 |
| new --forget：「X」是放在节目目录里的录音……--forget 去不掉它 | 这个录音是同一个盘硬链接进来的（或 `--copy` 拷进来的），就在节目目录里，不在 录音位置.json 的登记里 | 把它挪出节目目录（硬链接挪走、删掉都不影响原文件），改掉"录音顺序"（和"音轨对应"）里的它，再重新转写 |
| transcribe：录音顺序和实际的录音对不上 | 节目信息.md 的"录音顺序"写错了名字，或者漏写了一个文件（大小写、空格和下划线、带不带扩展名不讲究） | 照报错里列的实际文件名，按播放顺序写进"录音顺序"（顿号隔开），再转写。以前这种情况会悄悄按名字排序拼，前后可能拼反。报错说两个文件"名字只差大小写、空格或下划线"：照抄完整文件名（带扩展名），还不行就把其中一个改名 |
| transcribe：录音方式是"前后接着"，有 N 个录音，可"录音顺序"没写 | 几个录音前后接着拼，"录音顺序"空着（多半是已经有节目信息、又用 new 放进了补录或另一期，new 不会替你改节目信息） | 按播放顺序把文件名写进"录音顺序"再转写。以前会按名字排：补录排到正片前面、后半场排到前半场前面 |
| status / plan / finish / build：录音和上次转写时不一样了（新加了「补录.wav」、录音顺序改了、录音方式改了……） | 转写之后又放进了录音（补录、另一期），或者改了录音顺序、录音方式、音轨偏移，还没重新转写。全文、编排方案、精编版都还是旧录音的，照旧全文的时间去剪新录音会整段错位 | 改好 节目信息.md 的"录音方式""录音顺序"，在后台运行 `node "<技能>/tools/podcast/transcribe.mjs" "<节目>"` 重新转写，再 plan.mjs 按新全文核对方案、重新给主理人确认。在这之前 plan、finish、build 不做，`--confirm 编排`/`成品` 会被拦下 |
| status：上次转写半路断了：识别结果不在，全文还是旧的 / 上次转写半路断了：全文还没出来 / 全文 无 | 换了录音重新转写时被打断了（关了终端、宿主把进程杀了） | 重新运行 transcribe（会整期重新识别），再 plan.mjs 核对方案。现在换录音前会先删掉旧全文，断在半路也不会留下"新录音 + 旧全文"。转写做完之前，原来的编排方案、精编版、检查结果都是旧的：`--confirm 编排`/`成品` 会被拦下，clean 不清理 |
| check.mjs：接缝未通过，和原话差得太多（几十甚至上百个百分点） | 精编版剪的不是全文里的那些话：多半是录音在转写之后变过、转写半路断了 | 照提示运行 status，重新转写、核对方案后再出成品。不要当成识别误差放过去 |
| new / transcribe / status：录音「……」读不出来：文件不完整或者坏了（ffmpeg 说：moov atom not found / Invalid data……） | 录音软件崩溃、没正常结束（m4a 最常见：文件尾的 moov 没写进去），或者文件没传完、没下载完 | 用录音软件修复或重新导出一份；m4a 缺 moov 可以试 untrunc 这类修复工具（要一段同一台设备录的好文件当参照）。换掉坏的那个（名字照旧）再转写；不要了就挪出节目目录。重跑 transcribe 修不好，status 也不会再叫你重跑 |
| status 里录音多了一个 `._录音.mp3` 之类 | （旧版）Mac 在 U 盘、移动硬盘上留下的隐藏附属文件 | 现在点开头的文件一律不算录音，不用管；想清爽就删掉这些 4 KB 的小文件 |
| new.mjs：重名了，改了名字：rec.mp3 → rec_2.mp3 | 同一次给了两个同名的录音（不同文件夹里都叫 rec.mp3），或者这期已经有同名的另一个录音 | 正常，两个都留着。"录音顺序""音轨对应"里写新名字 |
| new.mjs：文件名里有空格或 & % ' 这类符号……换成了 _ | 这些字符在命令行里容易出错，放进来时改了名 | 正常。节目信息里写原名、新名都认 |
| transcribe / status：节目信息.md 的"音轨偏移"（或"音轨对应"）里写的「……」对不上任何录音 | 多轨时写错了文件名 | 照输出里列的实际录音名改好。"音轨偏移"写错转写会停下（不然音轨对不齐）；"音轨对应"写错只是称呼空着，改好后运行输出里给的 `speakers.mjs … --force` |
| 说话人.md 有 N 处填得不对（第几行：……） | 主理人手填时：竖线多了少了、编号改了或写成小写、同一个编号写了两行、一行填了两个人、填了"可能是……"之类的说明、整个写在括号里、称呼太长（中文超过 12 个字、英文名超过 30 个字母，会被当成说明）、写在表格外面 | 按提示改那几行（一行一个编号、"是谁"一栏只写一个称呼，拿不准就空着；英文全名太长可以只写名或姓），再运行 `node "<技能>/tools/podcast/fulltext.mjs" "<节目>"`。没认的行只是那个编号的称呼没换进全文，不影响剪辑 |
| 说话人.md 提醒（称呼已经用上了，不用改）：括号里的部分没进全文 | 称呼后面带了括号说明，比如"老王（主持人）" | 不用管：已经按括号外面的"老王"用上了。认人确认之后 status 不再提 |
| transcribe / status：录音里没识别出人声（一句都没有） | 整段是静音、只有底噪，或者放进来的不是这期的录音、用错了音轨 | 听一下录音，换成对的文件，再在后台运行 transcribe（换了录音会整期重新识别）。不用再跑 speakers |
| transcribe：全文没写完：EBUSY / EPERM … / status：全文没写完（识别结果比 全文.json 新） | 写全文时 全文.txt、全文提纲.md 或 编排方案.草稿.json 被别的程序占着（编辑器、预览），或者是只读的 | 关掉占用的程序、去掉只读，再运行同一条 transcribe：识别结果已经存好，不会重新识别。全文.json 最后才写，没写完时还是旧的，不会和 全文.txt 对不上 |

| 读不了 / 写不进 ……：正被别的程序占着，或者没有权限、是只读的 | 文件被编辑器、同步盘占着；从光盘、别的电脑、同步盘拷来的文件带着"只读"；或者没有读写权限 | 照提示关掉占着它的程序、去掉"只读"（整期一起改：`attrib -R /S /D "<节目目录>\*"`；Mac 用 `chmod -R u+w "<节目目录>"`），再运行同一条命令 |
| "磁盘空间不够：……大约要 x GB" | 转写或剪辑前算过，这个盘放不下 | 清出空间，或者把整个节目目录挪到空间大的盘（Windows 比如 D 盘，Mac 比如外接硬盘），照常运行同一条命令（节目目录换成新位置；之前输出里打印的完整命令带着旧路径，不要照抄）；做完的步骤不会重做 |
| transcribe / speakers / check / status：节目目录的路径太长了（N 个字） | Windows 上识别程序读 wav 用的是老接口，完整路径到 260 个字（中文也按一个字算）就读不了，原来只报一句英文 `Failed to read` | 把整个节目目录挪到浅一点的地方（比如 `D:\播客\第1期`），节目目录的完整路径不超过提示里说的字数，再对新位置运行同一条命令；做完的步骤不会重做 |
| clean.mjs：成品还没确认 / 确认之后又重剪过 / 编排方案（或人声处理、节目档案）在成品确认之后改过，先不清理 | 只有主理人确认了现在这版精编版、之后也没再改方案，才清中间文件（不然马上要重剪，清了又得重新转换） | 等他确认成品（改了方案的，先重出、再确认）；确定现在就要清加 `--force`（清了也能重剪，只是先要花几十秒重新转换录音） |
| clean.mjs：转写时用的录音「……」不在……原始录音不在，清掉转好的录音以后就没法重剪了 | 原始录音被删掉、挪走、改了名，或者别的盘上的没插 | 找回来再清。确定这期以后不会再剪才加 `--force` |
| clean.mjs：……还在跑，它正用着这些文件 | 转写、分说话人、出成品、剪辑、出对比（build --compare）或机器检查正在跑 | 等它跑完再清 |
| build / speakers：中间文件清理过，先重新转换录音 / status：转好的录音正在自动重新转换 | 之前运行过 clean.mjs，转好的录音删掉了 | 正常，自动转完接着做（实测 65 分钟的录音 4 秒；这几秒里 status 不会再说"第 1 步：转写正在跑"），只恢复转好的录音：识别、分说话人、全文都不动（不会套上后来加的常错词）。原始录音不在了就转不了，见上面"录音找不到了" |
| build / speakers：录音和当初转写时不一样了……自动补转只恢复转好的录音，不会悄悄重新识别，所以先停下 | 清理过中间文件之后，录音换过、重新导出过、改了音轨偏移，或者原文件在原位置被改过（硬链接的原文件被降噪保存、被同名文件覆盖），转出来的内容和当初对不上 | 问主理人。录音没换：把原来那份放回原处，再运行同一条命令。确实要按新录音做：单独运行 `node "<技能>/tools/podcast/transcribe.mjs" "<节目>"`（整期重新识别，句子编号会变），再运行 plan.mjs 按新全文改编排方案、给他看过，再剪。只是修改时间变了、内容一样的，不会停（录音文件只是修改时间变了时，build 剪之前、clean 清理之前都会先重新转换一次核对内容）。核对出内容不一样，会记下来：之后 status 说"录音文件在原位置改过"，确认成品、清理都拦下，直到放回原来那份或者重新转写 |
| build.mjs：第 N 句里找不到 startText / endText「……」，全文在上次检查编排方案之后变过 | 检查方案之后全文重出过（换了常错词、改了称呼规则后跑了 fulltext，或者重新识别过） | 先运行 plan.mjs，照它说的改好方案（多半是按新的写法改 startText / endText），再剪 |
| 处理后人声发闷、停顿时底噪一起一伏 | 这期录音不适合降噪或调平 | 编排方案里写 `"voice": "raw"`，重新确认"声音" |
