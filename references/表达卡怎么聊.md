# 表达卡怎么聊

表达卡是这条视频的"合同"：他想说什么、不想被说成什么。后面写稿、配画面、验收都拿它对照。

## 怎么问

一次只问一两个问题，等他答完再问下一个。不要一上来甩一张问卷。

| 要填的 | 可以这样问 | 什么算问到位 |
|---|---|---|
| 说给谁听 | "你想让谁看到这条？他现在卡在哪？" | 是一类具体的人，不是"所有人""年轻人" |
| 想说的一件事 | "如果只能说一句话，你想说什么？" | 一句话说得完，而且有立场 |
| 依据 | "你是怎么知道这一点的？有没有一次具体的经历？" | 有时间、地点、发生了什么；或者有数字、有出处 |
| 希望对方做什么 | "看完之后，你希望他今天做一件什么小事？" | 今天就能做，不需要准备 |
| 不想被说成什么 | "这个观点最容易被误解成什么？哪句话你不会说？" | 至少一条 |

## 追问到具体

他给的是形容词或大词时，不要自己替他展开，继续问：

- "要有深度" → "你说的深度，是指讲到哪一层？举个你觉得有深度的例子。"
- "很多人都这样" → "你见过的是谁？当时发生了什么？"
- "效果很好" → "好到什么程度？有没有前后对比的数？"
- "我想讲讲时间管理" → "时间管理里的哪一件事？你自己踩过的坑是哪个？"

## 题目太大怎么办

一句话讲不完，或者依据有三四条互不相干的，就是题目太大。给他两三个切小的方向，让他选一个，其余的记在卡片最后一行"下次再讲"。不要替他选。

## 怎么写进卡片

- 用他的原话。可以删口头语，不要换词。
- 你推断或补充的内容，行尾标"（待确认）"。逐条确认时，他点头的去掉标记，他摇头的删掉。
- 依据不够（只有观点没有经历）时，直接告诉他："这里需要一个你自己的例子，不然观众不信。"不要替他编。

## 确认门

把卡片从头到尾念给他，一条一条问"对不对"。全部确认后，把卡片最后的"本人确认"改成当天日期，再运行：

```
node "<技能>/tools/status.mjs" "<作品>" --confirm 表达卡
```

卡片确认后又改了内容，确认会自动失效，要重新走一遍确认门。

## 一个填好的例子

```markdown
## 说给谁听
刚开始做短视频、每条都想把所有知识点讲全的人。

## 我想说的一件事
一条短视频只说一件事。

## 依据
- 我自己前 10 条视频每条讲三四个点，完播率都在 10% 以下；改成一条一个点之后到了 30% 左右。
- 帮朋友改稿时，把 5 个要点砍成 1 个，他自己说"终于知道这条在讲什么了"。

## 希望对方看完做什么
把手上正在写的那条稿子，用一句话说出来试试。

## 不想被说成什么
不是说内容越少越好，是说一条只解决一个问题。
```
