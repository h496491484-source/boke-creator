# 播客编排原则

第 3 步用。你先读 全文提纲.md、再按需读 全文.txt，写 `编排方案.json`（可以从机器草稿 `编排方案.草稿.json` 改起），跑 `plan.mjs` 出 `编排方案.md` 给主理人过目。**主理人同意之前不动音频。**

这一步的价值在判断：留什么、删什么、为什么。机器能算时长、查对错，判断要你来做，并且每一刀都说得出理由。

## 先读完，再动手

1. 全文很长（1 小时约 2 万字）。先读 `全文提纲.md`：机器按停顿和说话人切成 2–4 分钟一块，每块一行（句子编号、时间、谁在说、开头结尾的原话节选），约全文的 1/10，先有整期的地图。提纲只是节选，不能代替原文。
2. 再到 全文.txt 里按〔编号〕读对应段落，边读边记一份自己的提纲：每个话题从第几句到第几句、谁讲的、讲了什么具体的事。主持人的提问通常就是话题的分界。要挑钩子、要删、拿不准讲了什么的块，一定读原文。
3. 标出三类东西：
   - **故事**：有人、有事、有数字或场面的经历（"说好回来买，我真回去了，花了一万多"）。最值得留。
   - **金句**：一句话能单独成立、能引起共鸣或争论的（"没买到时它是全部，买到后它只是一块表"）。片头钩子从这里挑。
   - **水分**：下面"删什么"里列的那些。

## 结构

| 板块 | 做法 |
|---|---|
| 片头（`kind: "hook"`） | 3–4 句原话快剪，合计 30–60 秒，每句不超过 20 秒。挑不同的人、不同的话题，能单独听懂、有画面或有冲突。这几句在正文里还会再出现，没关系。不管写在 sections 的哪儿，钩子都放在成品最前面：写在它前面的板块会排到它后面，所以钩子板块写在第一个 |
| 开场 | 用主持人自己的开场。节目有录好的固定片头（片头曲、固定开场白）的，写进节目档案的"片头"，build.mjs 会自动放在钩子之后，编排里不用管；录音里每期现场说一遍的开场白，照常留在开场 |
| 正文板块 | 4–7 个，**按原来的顺序**，通常一个主持人提问就是一个板块。板块名写成听众看得懂的问题或观点 |
| 结尾 | 主持人的总结和告别 |

- **默认不打乱顺序。** 多人对话里，后一个人常在回应前一个人；挪动段落会让回应对错人、意思变味。同一话题散在两处时，可以把后一处挪到前一处后面，但 plan.mjs 会提醒，在给主理人的说明里要点出来。几个录音前后接着拼的（补录、两期拼接），plan.mjs 每个录音文件各自看先后：从补录拿来插在哪儿都不算打乱顺序，同一个录音里的段前后颠倒了（哪怕挪到了补录后面）照样提醒。
- 板块之间会自动加约 3 秒的过渡音乐，片头有铺底音乐，结尾有片尾音乐（节目档案里可以换成节目自己的，或者不要）。
- 有节目档案的，先读"剪辑偏好"。和这份原则冲突的地方，听主理人的偏好。

## 删什么

按优先级，从上往下删，删够时长就停：

1. **听不清的**：几个人同时抢话、离话筒太远、背景太吵。
2. **现场流程**：举手投票、点名、调设备、"我们先休息一下"。
3. **重复的**：同一个意思第二次、第三次说；后面有人讲了同一类、但更具体的例子。
4. **跑题、发散的**：离开本期主题，聊不回来。
5. **过长的串场**：主持人的过渡说了很久，只留提问那一两句。
6. **隐私和风险**：真实全名、电话、单位、第三人的隐私、可能引起纠纷的指名道姓。这一类不论时长都要删，并且告诉主理人。
7. **为控制时长**：最后才删，删的时候写明"内容不差，为控制时长"。

**不要这样做：**
- 不要把某个人整个删光。每个参与者最好至少留一段；要删光某人，先问主理人。
- 不要在半句话中间断开，导致意思变了。尤其注意"不""没""但是""除非"这类词，删掉会让意思反过来。
- 不要把两个人的话拼在一起，造出谁都没说过的观点。
- 不要只因为识别错字多就删。错字只影响字幕，不影响音频；要看的是原声听不听得清。

## 切口

- `from`、`to` 是句子编号（全文里的〔数字〕），两头都包含。
- 一句话只要后半句时，用 `startText` 写上从哪几个字开始；只要前半句时，用 `endText` 写到哪几个字为止。这几个字要和全文里的原文一字不差。
- 句中的"呃""嗯"、超过 0.9 秒的停顿、段首的口头语，剪辑时会自动处理，不用你管。

## 时长

- 按 节目信息.md 的目标时长来。没写的话（还是模板里的提示，plan.mjs 不会把提示里的例子当成目标），先问主理人；一般是原长的 55–70%。
- plan.mjs 报的"成品约 N 分钟"已经算上了音乐和过渡。超了就按上面的优先级再删，短了就加回"为控制时长"删掉的段落。

## 编排方案.json 格式

```json
{
  "title": "该省省，该花花：11 个普通人的消费观",
  "titleOptions": ["标题一", "标题二", "标题三"],
  "theme": "一句话主题",
  "intro": ["简介第一段", "第二段"],
  "voice": "processed",
  "music": { "片头": "库:aurora", "过渡": "库:aurora", "片尾": "库:aurora" },
  "musicWhy": "一句话：为什么这期配这几首",
  "sections": [
    { "name": "片头", "kind": "hook", "parts": [
      { "from": 44, "to": 44, "startText": "后台", "label": "往年大家不会把没钱赤裸裸说出来" }
    ]},
    { "name": "开场", "parts": [{ "from": 1, "to": 23, "label": "主持人开场" }] },
    { "name": "一、最近印象最深的一次消费", "parts": [
      { "from": 24, "to": 38, "label": "说好回来买，我真回去了" },
      { "from": 39, "to": 57, "label": "双十一为什么这么安静" }
    ]}
  ],
  "cuts": [
    { "from": 58, "to": 70, "why": "几个人同时接话，听不清" }
  ]
}
```

- `label` 会出现在 编排方案.md 和节目简介的时间轴里（板块只有一段时，简介里只写板块名），写成听众看得懂的一句话。主理人确认编排之后再改 `label`，编排确认会失效，要重跑 plan、请他重新确认。
- **真正删掉内容靠 `sections`**：正文（不算片头钩子）没选进去的句子才会被删。`cuts` 只给每一段被删的内容写原因，不会真删——要删的句子还在 sections 的某段里，就得把那段拆开、跳过这几句。`cuts` 写的范围整个都还在正文里，plan.mjs 会报错；一部分还在，会提醒（范围写宽了就改准）。段两头用 startText / endText 只留半句的那一句不算。没写原因、超过 8 秒的删减，plan.mjs 会提醒。只在片头钩子里用、正文里没有的句子（比如补录只当片头）不算删掉，不用写进 `cuts`。片头钩子用了 `cuts` 里写着删掉的句子（正文里也没有），片头照样会放：plan.mjs 会提醒，念摘要时要说清楚，是有意只放片头的就把这条 `cuts` 去掉（原因明说"只"放片头、或"片头已经有了/用了"的不提醒，比如"只当片头用""片头已经有了，正文删掉"；只写"当片头""片头用"的、"不适合放片头""当片头太长"这种意思相反的照样提醒。最省事的是直接把这条 cuts 去掉）；删的原因是隐私、不同意公开这类的，plan.mjs 直接报错，换一句。
- `voice` 在第 4 步听过对比后再定：`"processed"`（处理）或 `"raw"`（不处理）。
- `music` 是这期的配乐，按下面"配乐怎么挑"选；不写就照节目档案（没有档案就是默认的 Aurora）。`musicWhy` 写一句理由，会出现在 编排方案.md 里给主理人看。
- `intro` 是节目简介的正文，一段一个字符串（写成一整个字符串也认，按空行分段；写成数字、对象，notes、finish 会停下说怎么改，什么都不动）。不要编造现场没说过的事；"录了多久""一共几个人"这类数字，要等主理人确认后再写；说话人还没认完时，不要点具体的人名。
- 机器草稿 `编排方案.草稿.json` 已经是这个格式：一块一个板块、全文都留着、`cuts` 是空的，名字、小话题、标题写着"待改"。另存为 `编排方案.json`，**删掉里面的 `说明` 一栏**（那段话说的是草稿），在另存的那份上改。plan.mjs 会提醒：还没改掉的"待改"（标题、标题备选、一句话主题、板块名、小话题）、留着的草稿 `说明`、没有片头钩子、板块太多、一句没删或者板块还是草稿那几块。还有"待改"时，`status --confirm 编排` 会拦下。
- plan.mjs 有错会一次全列出来（句子编号、startText/endText、正文重复用同一句、cuts 没生效、voice 写错、intro 写成了数字或对象……），一起改完再跑。`编排方案.json` 本身写坏了（中文引号、单引号、多一个逗号、少一个逗号），会报"格式写错了（第几行附近、原因）"；存成了 UTF-8 以外的编码（PowerShell 的 `Set-Content` 默认存 ANSI）也会说清楚。写文件用 `[IO.File]::WriteAllText(路径, 内容)`。
- plan.mjs 检查通过时，把每段开头和结尾的原文、全文句子编号的指纹、方案的指纹记在 `<节目>/方案原文.json`，不写回 `编排方案.json`（检查不改方案文件）。这个文件别删。build 和 status 靠它判断"方案检查过没有"（不看文件修改时间）。旧版做的节目没有这个文件：要先用现在的 plan.mjs 检查通过一次，才能确认编排、剪。
- 以后重新识别过（编号指纹变了），plan.mjs 拿记的原文核对现在的编号（同一板块里先按原文认，再按小标题，最后按"第几段"）：没改编号的、改错了编号的都会报错，并提示可能的新编号（开头、结尾分开说）。改好再跑，会再核一次；确认编号没错、只是重新识别后字不一样，才加 `--refresh`。重新识别后新加的段（比如插进来的补录）没有记的原文，确认编号没错后加 `--accept-new`，只收下新段。方案原文.json 不见了而这期以前检查过，plan.mjs 也会停下说清楚。旧方案里留着的 `check` 字段不用删，照样认。

## 配乐怎么挑

先看节目档案的"配乐"：写了"库:…"、自己的文件或"无"，就是主理人定好了，**不要在编排方案里写 music**。写"默认"、空着或没有档案，才按内容挑：

1. 运行 `node "<技能>/tools/podcast/music.mjs"`，看曲库里有哪些、各是什么情绪、适合什么内容。
2. 按这期的**整体语气**挑，不按字面话题：轻松闲聊配轻快或爵士，深夜长谈、个人经历配夜谈或温暖，观点讨论、知识类配沉静，开场想提气可以用振奋。拿不准就用 `库:aurora`。
3. 片头和片尾一般用同一首（听着首尾呼应）；过渡可以用同一首（从曲子里截一小段），也可以用一个"过渡音"（从头放，最多约 4 秒；`short-jingle` 本身就这么短，另外几首有十几秒，只放开头约 4 秒、在曲子中间淡出）。板块多（5 个以上）时过渡音更利落。
4. 话题沉重（疾病、去世、事故、争议事件）时，不要用轻快、振奋的；配沉静的，或者不要配乐（`"music": false`），并在 musicWhy 里说明。
5. 同一档节目每期都换风格会显得散。看到主理人连续几期都满意同一首，建议他在节目档案里固定下来。

主理人在第 5 步听成品时会听到配乐；不喜欢就换编号，重跑 plan → finish（= build → check → notes）。

## 给主理人看什么

不要把整份 编排方案.md 甩过去。plan.mjs 通过时打印的"可以直接念给主理人听"（也在 编排方案.md 开头的"先说结论"）已经有前三样：几个板块、各叫什么，片头用了哪几段、各是谁说的（开头十几个字）；原来多长、剪完多长；删得最多的几处、是谁的话、为什么删。照着说，再补后面几样，附上文件。打出来的是"先别给主理人看"时，先把"待改"、没写原因的删减改完再念。还没分说话人的节目，摘要里不会有"谁说的"，要你对照 全文.txt 补上；删的是某个人的大段发言，要特别点出来（plan.mjs 发现某个人的话一句都没留，会在"要留意"里提醒）：

1. 结构：几个板块、各叫什么，片头用了哪几句。
2. 时长：原来多长，剪完多长。
3. 删得最多的三四处：删了什么、为什么。特别点出删掉了谁的大段发言。
4. 有没有调动顺序，调了哪里。
5. 配乐选了哪几首、为什么（一句话）。
6. 请他重点看删减清单，说出想留下或想删掉的地方。
